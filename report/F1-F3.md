# F1 — The original architecture

Described as the **paper** presents it. Where the authors' code does something different,
that is flagged here and catalogued in `report/paper_code_divergences.md`; our
reconstruction follows the **code**, because the code is what produced the published
numbers.

## F1.1 The model

**Task.** Multivariate point forecasting: a look-back window
\(X_t \in \mathbb{R}^{C \times L}\) maps to a horizon \(Y_t \in \mathbb{R}^{C \times H}\).
For our cell \(C = 7\), \(L = 96\), \(H = 96\).

**The problem TQNet attacks.** Channel-attention forecasters (iTransformer, TimeXer) treat
the \(C\) variables as tokens and let attention learn inter-variable structure. Their
queries, keys and values all come from **one input window**, so the correlation map is
re-estimated from a single noisy sample every time. TQNet's claim is that inter-variable
correlation is a property of the *dataset*, not of the window, and should therefore be
learned once and held in parameters.

**The Temporal Query.** In \(\mathrm{Attention}(Q, K, V)\), TQNet replaces the
sample-derived \(Q\) with a slice of a learnable table

\[
\theta_{TQ} \in \mathbb{R}^{C \times W}
\]

where \(W\) is the dataset's dominant period. For a sample whose forecast begins at
absolute time \(t\), the query is the length-\(L\) cyclic slice of \(\theta_{TQ}\) starting
at \(t \bmod W\). \(K\) and \(V\) still come from the input window, so sample-specific
content is preserved while the *query* — what the model asks of each channel — is
dataset-level and phase-conditioned. On ETTh1, \(W = 24\), so \(\theta_{TQ}\) holds
\(24 \times 7 = 168\) parameters: **0.025%** of the model's 661,640 `[config]`.

**Forward pass**, with tensor shapes for a batch of \(b\):

| Step | Output shape |
|---|---|
| Instance normalisation (per-window mean and standard deviation removed) | \((b, 96, 7)\) |
| Transpose — **channels become the tokens** | \((b, 7, 96)\) |
| Temporal-Query multi-head attention, 4 heads; \(Q\) from \(\theta_{TQ}\), \(K = V =\) input; + residual | \((b, 7, 96)\) |
| Linear \(96 \rightarrow 512\) | \((b, 7, 512)\) |
| Two-layer GELU MLP, \(512 \rightarrow 512\); + residual | \((b, 7, 512)\) |
| Dropout, then Linear \(512 \rightarrow 96\) | \((b, 7, 96)\) |
| Transpose back, then de-normalisation | \((b, 96, 7)\) |

**The single most important structural fact, because the project's central finding turns on
it: attention runs over the 7 channels, not over the 96 time steps.** The attention map is
\(7 \times 7\). All temporal modelling is done by the MLP acting on each channel's
96-dimensional history. This is what bounds what ETTh1 can demonstrate about the mechanism,
and F6 develops it.

**Where the code differs from this description** (`report/paper_code_divergences.md`):
the paper's Equation 3 scales attention logits by \(1/\sqrt{L} = 1/\sqrt{96}\), while
`nn.MultiheadAttention` scales by \(1/\sqrt{d_\text{head}} = 1/\sqrt{24}\), making the
logits **twice** as large; the code's MLP ends on a second GELU where Equation 5 ends on a
Linear; \(\theta_{TQ}\) is stored transposed, as \((W, C)\); and the cyclic phase is taken
at the **first forecast step** rather than the window start, which is harmless here only
because \(96 \bmod 24 = 0\).

## F1.2 The loss

**Mean squared error, on z-scored values.** `exp/exp_main.py:_select_criterion` returns
`nn.MSELoss`. The scaler is fitted on training rows `[0, 8640)` only and applied to the
whole series, so the loss — and every metric in F2 and F3 — is dimensionless. Upstream's
de-normalisation block in `test()` is commented out, so no number in this report is in
degrees or kilowatts.

## F1.3 The training objective

Minimise MSE over training windows, stride 1, with:

- **Adam** (`exp/exp_main.py:_select_optimizer`), learning rate \(10^{-3}\).
- **Schedule `type3`**: constant for 3 epochs, then \(\times 0.8\) per epoch
  (`utils/tools.py:adjust_learning_rate`).
- **30 epochs maximum, early stopping with patience 5 on validation MSE.**
- **Model selection is on validation, never on test**: the checkpoint with the best
  validation loss is reloaded before the test split is read once.

## F2.1 The metrics the paper reports

**MSE and MAE only**, on z-scored data, averaged over every forecast step, channel and
window. No interval, quantile or variance is reported anywhere; the model emits point
forecasts alone. Our own reporting adds RMSE and MdAE because the course requires them —
`report/metrics.md` gives the definitions and explains why MAPE and SMAPE are excluded
(z-scored data crosses zero in every channel, so a percentage error divides by ≈ 0).

Three seeds (2024/2025/2026), ETTh1, reported by the authors themselves. This is the most

meaningful and this report does not compute them.

## F2.4 The dataset as the paper describes it — Table 1, p. 5

7 channels, hourly, electricity domain, \(W = 24\), and **14,400 timesteps**. The file
`ETTh1.csv` has **17,420 rows**; the authors' loader hard-stops at 14,400 and silently
discards the final 3,020 (≈ 4 months). The paper never mentions this. We follow the loader,
because that is what produced the published numbers — see
`report/paper_code_divergences.md`.

## F2.5 What the paper does not report

Relevant to F3 and F6 because it bounds what can be checked:

- **No ablation on any ETT dataset.** The Temporal Query is ablated only on Electricity,
  PEMS03 and PEMS04 — all with more than 100 channels. There is no published evidence that
  it contributes anything at \(C = 7\).
- **No uncertainty of any kind**, and no per-channel or per-step error breakdown.
- **No wall-clock for ETTh1**, so the efficiency claim cannot be checked on this cell.

# F3 — Our reconstruction, against the paper

## F3.0 What "reconstruction" means here, stated plainly

**We vendored the authors' model code at commit `15e19cb2` and re-ran it; we
re-implemented the data path and the metrics independently.** `common/data.py`,
`common/split.py` and `common/metrics.py` are ours, written from the paper and the loader's
behaviour, and `tests/test_data.py` checks our windows element-wise against upstream's own
`Dataset_ETT_hour`. The architecture was **not** rewritten from scratch.

That is what makes the agreement below meaningful rather than circular — an independent data
path and an independent metric reproduce the authors' number — but a reader must not be left
to assume we re-implemented the network. `docs/04-paper-vs-upstream-vs-ours.md` §4.3 is the
longer form of this statement.

Fourteen changes were made to the vendored tree, all catalogued in
`docs/02-architecture-and-implementation.md` §2.6. None touches the model, the data, the
split, the loss, the optimiser or the metric; they exist because **unmodified upstream code
cannot run on any current library version** — it calls a pandas API removed in 2.0 and a
numpy alias removed in 2.0.

horizon exceeds 2σ.

## F3.3 Against the seasonal-naive baseline

A reproduction that matches the paper says nothing about whether the model is any good.
The baseline is what answers that, and it is deliberately a hard one: **seasonal-naive at
period 24** — repeat the last observed day — evaluated on the *identical* 2,785 test
windows, the same z-scored scale, the same train-fitted scaler, and asserting the same
split fingerprint. `tools/run_baseline.py` takes a `Windows` object so it cannot silently
use different windows.

The point of choosing period 24 is that **it encodes exactly the same assumption TQNet is
given by `--cycle 24`**: that ETTh1 repeats daily. So the gap below is not "model versus
nothing"; it is what the network adds *on top of already knowing the period*.

Record: `results/runs/baseline-seasonal_naive_24-sna-h96-1785426202205168000.json`. Split
`[test]`.

| Metric | Seasonal-naive | Our reconstruction | Reduction |
|---|---|---|---|
| MSE | `0.512225108181955` | `0.37104994668966473` | **27.6%** |
| MAE | `0.43330271118779884` | `0.3927239906699211` | **9.4%** |
| RMSE | `0.7156990346381327` | `0.6091386924910162` | **14.9%** |
| MdAE | `0.26066610775972177` | `0.2512602503411472` | **3.6%** |

**The four reductions disagree, and that disagreement is the finding.** They fall
monotonically as the metric becomes more robust to outliers: 27.6% on squared error, 9.4%
on mean absolute error, 3.6% on *median* absolute error. A single number cannot be quoted
here without choosing a story, so all four are given.

What that pattern means: TQNet's advantage over repeating yesterday is concentrated almost
entirely in the **hard windows**. On a typical window — the median one — it is only about
3.6% better than seasonal-naive. The 27.6% headline is earned on the minority of windows
where the naive forecast fails badly and the network does not.

The reconstruction's own error distribution says the same thing from the other direction:
**MAE / MdAE = 1.563**, so the mean absolute error sits more than half again above the
median. The errors are strongly right-skewed and the headline MSE is carried by a tail.

This is the honest frame for the whole study, and F6 develops it: on this dataset the
model's measurable contribution is tail-risk reduction rather than typical-case accuracy,
which is also why a mechanism ablated at \(C = 7\) is so hard to detect against a σ of
0.00215.

## F3.4 Our noise floor, and why it governs everything after this section

| Quantity | Value | Source |
|---|---|---|
| Our three-seed sd, \(H = 96\) | **`0.0021541981747125473`** `[test]` | `report/factsheet.md` §5 |
| Paper's three-seed sd, \(H = 96\) | 0.001 | Table 9, p. 18 |
| TQNet's claimed margin at \(H = 96\) | 0.004 | Table 5, p. 15 |

**Our noise floor is roughly half the entire effect TQNet is famous for.** σ is also **not
monotonic** in the horizon — it falls from \(H = 96\) to \(H = 192\) before rising sharply
to 0.0228 at \(H = 720\) — so reusing the \(H = 96\) value everywhere would be wrong by an
order of magnitude at the long end. Every verdict in F4–F6 is measured against the σ of its
own horizon for this reason.

## F3.5 Protocol and integrity checks behind the numbers above

- **Split**, chronological 12/4/4 months: train `[0, 8640)`, validation `[8544, 11520)`,
  test `[11424, 14400)`. Validation and test begin 96 rows early so their first *target*
  lands on the month boundary; their inputs reach back, their targets do not overlap.
- **Fingerprint** `b66ee6b47e2b2eb8` at \(L = H = 96\), asserted in code by
  `common.results.assert_split_hash` on **every** ETTh1 run, and recorded per horizon in
  `results/split_hash.txt`. A run that does not assert is not a result.
- **Evaluation**: rolling-origin, stride 1, one fixed model — the paper's own protocol.
  Walk-forward was deliberately **not** added as a second protocol, because it refits per
  fold and its numbers would not be comparable to the paper's.
- **Test is read once**, after training completes, never during.
- **Leakage audit**: ten stages ruled separately, 7 CLEAN and 3 DISCLOSE, verdict **PASS**
  (`report/audit.md`, `results/audit.json`). It was run by the team member who did not write
  the data path. The three disclosures are the input reach-back above, a test loss printed
  each epoch but never used for early stopping, and metrics being on the z-scored scale.
- **Dataset**: `ETTh1.csv`, sha256
  `f18de3ad269cef59bb07b5438d79bb3042d3be49bdeecf01c1cd6d29695ee066`, downloaded from a
  pinned ETDataset commit and verified on fetch. Not committed; the digest is the evidence.

## F3.6 What is not claimed here

- **No efficiency or wall-clock comparison.** No reconstruction timing was ever recorded, at
  any horizon, so there is no baseline to compare against. Arm D's twelve timings exist but
  have nothing to be measured against, and they are incoherent as a compute measure anyway —
  \(H = 96\) averages 242 s while \(H = 336\) averages 98 s, which reflects early-stopping
  epoch counts and machine load rather than architecture cost.
- **No baseline comparison at horizons beyond 96.** `tools/run_baseline.py` has only been
  run at \(H = 96\); §F3.3 is that horizon alone.
- **The ETTh1 ablation is not reported in F3.** It is not a reproduction — the paper never
  ran it — and it belongs to F6.
